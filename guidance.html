요청사항 스마트 안내 — 구현 가이드

iOS(SwiftUI) · Android(Compose) 대상. 왼쪽 프로토타입이 스펙의 기준이며, 값은 Figma와 동기화돼 있습니다.

개요상태감지 로직 컴포넌트예시 코드텍스트 필드 카피·i18n접근성엣지·세션

1개요

입력 텍스트의 키워드를 결정론적으로(규칙 매칭) 감지해, 관련 정책 안내 카드를 입력창 바로 아래에 인라인으로 보여줍니다. 생성형 AI가 아닙니다 — LLM 호출·비결정 출력 없음. 8개 기본 단어(카테고리)에 대한 변형·오타 키워드를 매칭하며, 서버 없이 클라이언트에서만 동작합니다. (Notion 스펙 TADA-5627 기준)

데이터 흐름: 입력(debounce 520ms) → detect(text) → [Advisory] → 상태 매핑 → 카드 리스트 렌더. 네트워크 왕복이 없으므로 기본은 즉시 표시입니다.

핵심 원칙 — ① 규칙 매칭이라 즉시성(스켈레톤은 실제 async 소스일 때만) ② 감지된 안내는 가리지 않고 전부 표시(마지막 입력 키워드가 위) ③ 문구는 현재 예약 조건 기준으로 분기(§3) ④ 정책 문구는 단정적, 어시스트 헤더만 부드럽게.

2상태 머신

상태조건표시
empty입력 없음/공백얇은 헬퍼 한 줄 "참고할 안내가 있으면 여기에 보여드려요."
analyzing실제 async 소스일 때만스켈레톤(shimmer) + "요청 내용 분석 중"
result(N)키워드 1개 이상어시스트 헤더 + 카드 N개(전부)
noResult입력은 있으나 키워드 0개헬퍼 "지금은 따로 안내드릴 내용이 없어요."
error규칙 로드 실패 등조용히 숨김 — 뷰 자체를 렌더하지 않음

부가 상태: CTA는 입력이 비면 disabled(#99A5C0). 키보드 up/down에 따라 CTA가 키보드 위로 부상(§6).

3감지 로직

  • 딕셔너리: 카테고리(기본 단어)마다 kws[](변형·오타). 예: 카시트 / 카싯트 / car seat / 아기 / 쌍둥이. 문장에서 가장 먼저 등장하는 변형 위치를 카테고리 대표 위치로.
  • 정렬: 카테고리별 대표 위치 내림차순 → 마지막에 입력된 키워드가 카드 맨 위. 감지된 카테고리는 전부 표시.
  • 디바운스: 520ms(규칙 매칭이라 짧게). 실제 서버 조회로 바뀌면 스켈레톤 노출.
  • 오타: 변형 배열로 흡수(카싯트→카시트, 강쥐→강아지). 형태소 분석 아님 — 부분 문자열 indexOf 매칭.
  • 중복 방지: 카테고리 id 기준 1카테고리=1카드(같은 카테고리의 여러 변형이 매칭돼도 1개).
  • 컨텍스트 분기: 일부 카테고리는 키워드가 트리거하고, 문구는 예약 조건(rideType·carSeatOption·예약종류)으로 선택. 예약이 바뀌면(US-04) 현재 조건 기준으로 재계산.

알려진 이슈 — 부분 문자열(indexOf) 매칭의 오탐 · 실개발 전 정책 결정 필요.
  • 짧은/흔한 키워드 오탐: 대기→"대기업/대기실", 3인·4인→"3인분/4인용", 개월→"6개월 전"(시간), 사람(광범위), 010→"2010".
  • 카테고리 교차 중첩: "펫캐리어" 입력 시 반려동물(펫캐리어) + 짐(캐리어)이 동시 감지 → 카드 2개.
  • 대응 옵션(택1): ① 단어 경계 매칭(정규식 \b·형태소) ② 제외어 목록 ③ 카테고리 우선순위. 현재 프로토타입은 스펙 그대로라 이 오탐이 재현됩니다.

4컴포넌트 구성

  • 입력 필드 — 회색 well(유일한 편집 표면). focus 시 #000 보더. 하단 우측 카운터.
  • 어시스트 헤더 — ✦ + "요청 내용에서 참고할 점 N개를 찾았어요"(항상 above-the-fold, 개수 노출).
  • 안내 카드 — [키워드 라벨] → [제목] → [본문] → (선택)[액션칩 우측]. 박스 없음, 상단 hairline으로 구분.
  • CTA — 전체폭, 하단 고정, 키보드 위로 부상(§6).
  • 발견성 3종nice-to-have — ① 헤더 개수 ② 가려진 안내 "N개 더 있어요 ↓" 유도칩 ③ 스크롤 시 접힌 입력 앵커. ①은 Figma 반영됨, ②③은 프로토타입 전용(런타임 어포던스).

감지 함수

iOS · SwiftUI
func detect(_ text: String, _ ctx: Ctx) -> [Advisory] {
    var hits: [(adv: Advisory, at: Int)] = []
    for rule in rules {
        var firstAt: Int? = nil          // 카테고리 내 변형 중 가장 먼저 등장
        var matched = ""
        for v in rule.kws {
            if let r = text.range(of: v) {
                let at = text.distance(from: text.startIndex, to: r.lowerBound)
                if firstAt == nil || at < firstAt! { firstAt = at; matched = v }
            }
        }
        if let at = firstAt {
            hits.append((Advisory(id: rule.id, keyword: matched, title: rule.title,
                body: rule.msg(ctx), action: rule.action), at))   // 문구는 예약 조건으로 확정
        }
    }
    return hits.sorted { $0.at > $1.at }.map(\.adv)   // 마지막 입력이 위로
}
Android · Compose
fun detect(text: String, ctx: Ctx): List<Advisory> =
    rules.mapNotNull { rule ->
        rule.kws
            .mapNotNull { v -> text.indexOf(v).takeIf { it >= 0 }?.let { it to v } }
            .minByOrNull { it.first }                 // 가장 먼저 등장
            ?.let { (at, word) ->
                Advisory(rule.id, word, rule.title, rule.msg(ctx), rule.action) to at
            }
    }
    .sortedByDescending { it.second }                 // 마지막 입력이 위로
    .map { it.first }

상태 + 디바운스

iOS · Combine
enum GuidanceState: Equatable {
    case empty            // 얇은 헬퍼 한 줄
    case analyzing        // 실제 async 소스일 때만
    case result([Advisory])
    case noResult
    // error → case 없음: 뷰를 렌더하지 않음(조용히 숨김)
}

// 텍스트 + 예약 조건 둘 다 감시 → 조건이 바뀌면 문구 재계산(US-04)
Publishers.CombineLatest($text, $ctx)
    .debounce(for: .milliseconds(520), scheduler: RunLoop.main)
    .map { (t, ctx) -> GuidanceState in
        let s = t.trimmingCharacters(in: .whitespacesAndNewlines)
        guard !s.isEmpty else { return .empty }
        let hits = detect(t, ctx)
        return hits.isEmpty ? .noResult : .result(hits)
    }
    .assign(to: &$state)
Android · Flow
sealed interface GuidanceState {
    data object Empty : GuidanceState
    data object Analyzing : GuidanceState
    data class Result(val items: List<Advisory>) : GuidanceState
    data object NoResult : GuidanceState
    // Error → 상태 없음: 컴포저블 미방출(조용히 숨김)
}

// 텍스트 + 예약 조건(ctxFlow) 결합 → 조건 변경 시 재계산(US-04)
val state: StateFlow<GuidanceState> =
    combine(snapshotFlow { field.text }, ctxFlow) { t, ctx -> t to ctx }
        .debounce(520)
        .distinctUntilChanged()
        .mapLatest { (t, ctx) ->
            when {
                t.isBlank()              -> GuidanceState.Empty
                detect(t, ctx).isEmpty() -> GuidanceState.NoResult
                else                     -> GuidanceState.Result(detect(t, ctx))
            }
        }
        .stateIn(scope, SharingStarted.WhileSubscribed(5_000), GuidanceState.Empty)

6텍스트 필드 신규 DS

요청사항·탑승사유 입력에 쓰는 멀티라인 텍스트 필드 + 글자수 카운터. 기존 디자인 시스템에 없던 컴포넌트라 여기서 정의합니다. 정확한 값은 Figma 입력 컴포넌트 56952:84251가 기준.

이름 제안

텍스트 필드 (Text Field) — 이 화면은 멀티라인 + 카운터 variant입니다. iOS TextField/TextEditor, Android TextField와 이름이 이어져 개발 소통이 쉽습니다. "텍스트 박스 / 텍스트 영역(Text Area)"은 웹 용어라 앱 DS에선 지양을 권장합니다.

구조 (Anatomy)

  • ① 컨테이너(well) — 회색 배경, radius 8. 화면에서 유일한 편집 표면(안내 카드와 역할을 색으로 구분).
  • ② 입력 텍스트 / 플레이스홀더 — 멀티라인, auto-grow.
  • ③ 글자수 카운터 — 하단 우측 고정(컨테이너 하단 여백으로 공간 확보).
  • (선택) ④ 헬퍼/에러 문구 — 컨테이너 하단, 에러 상태에서만.

동작 (Behavior)

  • Auto-grow — min-height에서 시작해 내용에 따라 max까지 성장. 글자 한도가 자연 최대치라 대부분 스크롤 없음.
  • 하드 리밋 — 한도(요청사항 100 / 탑승사유 150) 초과 입력 차단. 도달 시 카운터만 브랜드 블루(#32A2FA).
  • Focus — #000 1px 보더 등장, blur 시 제거. well 배경색은 유지.
  • 카운터 — 실시간 갱신, 현재값만 Bold.

구현 코드

iOS · SwiftUI
struct RequestTextField: View {
    @Binding var text: String
    @FocusState private var focused: Bool
    let limit: Int              // 100(요청사항) / 150(탑승사유)
    let placeholder: String

    var body: some View {
        VStack(alignment: .trailing, spacing: 8) {
            ZStack(alignment: .topLeading) {
                if text.isEmpty {
                    Text(placeholder).spoqa(.regular, 15)
                        .foregroundColor(Color(hex: focused ? 0x9DA0AE : 0x73788B))
                }
                TextEditor(text: $text)
                    .spoqa(.regular, 15).foregroundColor(.black)
                    .focused($focused)
                    .scrollContentBackground(.hidden)              // iOS 16+
                    .frame(minHeight: 52)
                    .onChange(of: text) { text = String($0.prefix(limit)) }   // 하드 리밋
            }
            HStack(spacing: 0) {
                Text("\(text.count)").spoqa(.bold, 12)
                    .foregroundColor(Color(hex: text.count >= limit ? 0x32A2FA : 0x73788B))
                Text("/\(limit)").spoqa(.regular, 12).foregroundColor(Color(hex: 0x73788B))
            }
        }
        .padding(16)
        .background(Color(hex: 0xF5F6F7))
        .clipShape(RoundedRectangle(cornerRadius: 8))
        .overlay(RoundedRectangle(cornerRadius: 8)
            .stroke(.black, lineWidth: focused ? 1 : 0))           // focus 시 #000
    }
}
Android · Compose
@Composable
fun RequestTextField(
    value: String,
    onValueChange: (String) -> Unit,
    limit: Int,                       // 100 / 150
    placeholder: String,
) {
    var focused by remember { mutableStateOf(false) }
    Column(
        Modifier.fillMaxWidth()
            .clip(RoundedCornerShape(8.dp))
            .background(Color(0xFFF5F6F7))
            .then(if (focused) Modifier.border(1.dp, Color.Black, RoundedCornerShape(8.dp)) else Modifier)
            .padding(16.dp),
        horizontalAlignment = Alignment.End,
    ) {
        BasicTextField(
            value = value,
            onValueChange = { if (it.length <= limit) onValueChange(it) },   // 하드 리밋
            textStyle = TextStyle(fontFamily = Spoqa, fontSize = 15.sp, color = Color.Black),
            cursorBrush = SolidColor(Color.Black),
            modifier = Modifier.fillMaxWidth().heightIn(min = 52.dp)
                .onFocusChanged { focused = it.isFocused },
            decorationBox = { inner ->
                if (value.isEmpty()) Text(
                    placeholder, fontFamily = Spoqa, fontSize = 15.sp,
                    color = Color(if (focused) 0xFF9DA0AE else 0xFF73788B),
                )
                inner()
            },
        )
        Spacer(Modifier.height(8.dp))
        Row {
            Text("${value.length}", fontWeight = FontWeight.Bold, fontSize = 12.sp,
                color = if (value.length >= limit) Color(0xFF32A2FA) else Color(0xFF73788B))
            Text("/$limit", fontSize = 12.sp, color = Color(0xFF73788B))
        }
    }
}
멀티라인 auto-grow: iOS TextEditor는 내용에 따라 자동 확장(min/maxHeight로 상·하한). Android BasicTextField는 기본 확장 + heightIn(min, max). 카운터는 well 내부 하단 우측에 고정 배치.

요청사항·탑승사유가 같은 컴포넌트를 공유하므로 어시스트 카피는 기능 중립어 "요청 내용"으로 통일(앱바 타이틀만 화면별로 다름). {N}은 카드 개수, 1개도 "1개"로 표기(복수 규칙 단순화).

8접근성

  • 대비(흰 배경): 입력 #000 ≈21:1 · 제목 #262A38 ≈14:1 · 본문 #383D4F ≈10:1 — 모두 AA 통과. 키워드/카운터 #73788B ≈4.6:1(AA 경계). 어시스트 헤더 #868B9C ≈3.4:1은 보조 라벨로만(핵심 정보 아님).
  • 탭 타깃: 액션칩·유도칩·CTA 최소 44×44pt(iOS)/48dp(Android).
  • 스크린리더: 카드는 "키워드, 제목, 본문" 순서로 묶어 읽기(그룹). 카운터는 "N/100자 입력됨". 어시스트 ✦는 accessibilityHidden.
  • 모션: 스켈레톤 shimmer·페이드는 prefers-reduced-motion/Reduce Motion에서 생략.

9엣지 케이스 & 세션

  • 최대 글자: 요청사항 100 / 탑승사유 150. 한도 도달 시 카운터 #32A2FA(입력은 계속 막힘, 에러 톤 아님).
  • 오버플로우: 카드가 많아 키보드 뒤로 가려지면 "N개 안내 더 있어요 ↓" 유도칩nice-to-have.
  • 세션 저장 규칙(플로우 정의): 저장된 요청사항은 세션 내 유지 · 작성완료=저장, 상단 뒤로가기=미저장 · 빈 곳 클릭=필드 디폴트+키보드 내림. 세션 이탈 = 예약 성공 / 예약 홈 복귀 / 앱 종료. 작성 중·기존 예약 불러오기에서는 값 미저장.

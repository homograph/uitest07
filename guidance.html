요청사항 스마트 안내 — 구현 가이드

iOS(SwiftUI) · Android(Compose) 대상. 왼쪽 프로토타입이 스펙의 기준이며, 값은 Figma와 동기화돼 있습니다.

개요상태감지 로직 컴포넌트예시 코드텍스트 필드 개발 수정 요청 카피·i18n접근성엣지·세션

1개요

입력 텍스트의 키워드를 결정론적으로(규칙 매칭) 감지해, 관련 정책 안내 카드를 입력창 바로 아래에 인라인으로 보여줍니다. 생성형 AI가 아닙니다 — LLM 호출·비결정 출력 없음. 8개 기본 단어(카테고리)에 대한 변형·오타 키워드를 매칭하며, 서버 없이 클라이언트에서만 동작합니다. (Notion 스펙 TADA-5627 기준)

데이터 흐름: 입력(debounce 520ms) → detect(text) → [Advisory] → 상태 매핑 → 카드 리스트 렌더. 네트워크 왕복이 없으므로 기본은 즉시 표시입니다.

핵심 원칙 — ① 규칙 매칭이라 즉시성(스켈레톤은 실제 async 소스일 때만) ② 감지된 안내는 가리지 않고 전부 표시(마지막 입력 키워드가 위) ③ 문구는 현재 예약 조건 기준으로 분기(§3) ④ 정책 문구는 단정적, 어시스트 헤더만 부드럽게.

2상태 머신

상태조건표시
empty입력 없음/공백✦ 헬퍼(회색 별 #868B9C) "요청 내용을 분석해 참고할 만한 정보를 안내해 드려요."
analyzing실제 async 소스일 때만스켈레톤(shimmer) + "요청 내용 분석 중"
result(N)키워드 1개 이상어시스트 헤더 + 카드 N개(전부)
noResult입력은 있으나 키워드 0개empty와 동일 헬퍼(Figma "결과없음/입력없음" 단일 상태)
error규칙 로드 실패 등조용히 숨김 — 뷰 자체를 렌더하지 않음

부가 상태: CTA는 입력이 비면 disabled(#99A5C0). 키보드 up/down에 따라 CTA가 키보드 위로 부상(§6).

3감지 로직

  • 딕셔너리: 카테고리(기본 단어)마다 kws[](변형·오타). 예: 카시트 / 카싯트 / car seat / 아기 / 쌍둥이. 문장에서 가장 먼저 등장하는 변형 위치를 카테고리 대표 위치로.
  • 정렬: 카테고리별 대표 위치 내림차순 → 마지막에 입력된 키워드가 카드 맨 위. 감지된 카테고리는 전부 표시.
  • 디바운스: 520ms(규칙 매칭이라 짧게). 실제 서버 조회로 바뀌면 스켈레톤 노출.
  • 오타: 변형 배열로 흡수(카싯트→카시트, 강쥐→강아지). 형태소 분석 아님 — 부분 문자열 indexOf 매칭.
  • 중복 방지: 카테고리 id 기준 1카테고리=1카드(같은 카테고리의 여러 변형이 매칭돼도 1개).
  • 컨텍스트 분기: 일부 카테고리는 키워드가 트리거하고, 문구는 예약 조건(rideType·carSeatOption·예약종류)으로 선택. 예약이 바뀌면(US-04) 현재 조건 기준으로 재계산.

사전 소스 = 클라이언트 번들 (확정) — Notion 스펙상 "웹만 배포(서버 없음), 클라에서 키워드 기반으로만 구성"(8/6 결정). 원격 갱신 불필요. 전체 키워드·오타 목록은 Notion TADA-5627 '스펙 기준'이 정본이며, 프로토타입에는 전체 목록을 그대로 반영했습니다(코드 예시에는 대표 변형만 발췌).
알려진 이슈 — 부분 문자열(indexOf) 매칭의 오탐 · 실개발 전 정책 결정 필요.
  • 짧은/흔한 키워드 오탐: 대기→"대기업/대기실", 3인·4인→"3인분/4인용", 개월→"6개월 전"(시간), 사람(광범위), 010→"2010".
  • 카테고리 교차 중첩: "펫캐리어" 입력 시 반려동물(펫캐리어) + 짐(캐리어)이 동시 감지 → 카드 2개.
  • 대응 옵션(택1): ① 단어 경계 매칭(정규식 \b·형태소) ② 제외어 목록 ③ 카테고리 우선순위. 현재 프로토타입은 스펙 그대로라 이 오탐이 재현됩니다.

4컴포넌트 구성

  • 입력 필드 — 회색 well(유일한 편집 표면). focus 시 #000 보더. 하단 우측 카운터.
  • 어시스트 헤더 — ✦ + "요청 내용에서 참고할 점 N개를 찾았어요"(항상 above-the-fold, 개수 노출).
  • 안내 카드 — [키워드 라벨] → [제목] → [본문] → (선택)[액션칩 우측]. 박스 없음, 상단 hairline으로 구분.
  • CTA — 전체폭, 하단 고정, 키보드 위로 부상(§6).
  • 발견성 2종nice-to-have — ① 헤더 개수 ② 가려진 안내 "N개 더 있어요 ↓" 유도칩. ①은 Figma 반영됨, ②는 프로토타입 전용(런타임 어포던스).

감지 함수

iOS · SwiftUI
func detect(_ text: String, _ ctx: Ctx) -> [Advisory] {
    var hits: [(adv: Advisory, at: Int)] = []
    for rule in rules {
        var firstAt: Int? = nil          // 카테고리 내 변형 중 가장 먼저 등장
        var matched = ""
        for v in rule.kws {
            if let r = text.range(of: v) {
                let at = text.distance(from: text.startIndex, to: r.lowerBound)
                if firstAt == nil || at < firstAt! { firstAt = at; matched = v }
            }
        }
        if let at = firstAt {
            hits.append((Advisory(id: rule.id, keyword: matched, title: rule.title,
                body: rule.msg(ctx), action: rule.action), at))   // 문구는 예약 조건으로 확정
        }
    }
    return hits.sorted { $0.at > $1.at }.map(\.adv)   // 마지막 입력이 위로
}
Android · Compose
fun detect(text: String, ctx: Ctx): List<Advisory> =
    rules.mapNotNull { rule ->
        rule.kws
            .mapNotNull { v -> text.indexOf(v).takeIf { it >= 0 }?.let { it to v } }
            .minByOrNull { it.first }                 // 가장 먼저 등장
            ?.let { (at, word) ->
                Advisory(rule.id, word, rule.title, rule.msg(ctx), rule.action) to at
            }
    }
    .sortedByDescending { it.second }                 // 마지막 입력이 위로
    .map { it.first }

상태 + 디바운스

iOS · Combine
enum GuidanceState: Equatable {
    case empty            // 얇은 헬퍼 한 줄
    case analyzing        // 실제 async 소스일 때만
    case result([Advisory])
    case noResult
    // error → case 없음: 뷰를 렌더하지 않음(조용히 숨김)
}

// 텍스트 + 예약 조건 둘 다 감시 → 조건이 바뀌면 문구 재계산(US-04)
Publishers.CombineLatest($text, $ctx)
    .debounce(for: .milliseconds(520), scheduler: RunLoop.main)
    .map { (t, ctx) -> GuidanceState in
        let s = t.trimmingCharacters(in: .whitespacesAndNewlines)
        guard !s.isEmpty else { return .empty }
        let hits = detect(t, ctx)
        return hits.isEmpty ? .noResult : .result(hits)
    }
    .assign(to: &$state)
Android · Flow
sealed interface GuidanceState {
    data object Empty : GuidanceState
    data object Analyzing : GuidanceState
    data class Result(val items: List<Advisory>) : GuidanceState
    data object NoResult : GuidanceState
    // Error → 상태 없음: 컴포저블 미방출(조용히 숨김)
}

// 텍스트 + 예약 조건(ctxFlow) 결합 → 조건 변경 시 재계산(US-04)
val state: StateFlow<GuidanceState> =
    combine(snapshotFlow { field.text }, ctxFlow) { t, ctx -> t to ctx }
        .debounce(520)
        .distinctUntilChanged()
        .mapLatest { (t, ctx) ->
            when {
                t.isBlank()              -> GuidanceState.Empty
                detect(t, ctx).isEmpty() -> GuidanceState.NoResult
                else                     -> GuidanceState.Result(detect(t, ctx))
            }
        }
        .stateIn(scope, SharingStarted.WhileSubscribed(5_000), GuidanceState.Empty)

6텍스트 필드 DS 컴포넌트

자유 텍스트를 입력하는 기본 입력 컴포넌트. 특정 화면·기능에 종속되지 않는 재사용 프리미티브로 정의합니다 — 요청사항 스마트 안내는 이 컴포넌트를 쓰는 사용 예시 하나일 뿐. 정확한 값은 Figma 입력 컴포넌트 56952:84251가 정본.

1. 정의 · 용도

  • 정의 — 사용자가 자유 텍스트를 입력하는 기본 필드. 단일행·멀티라인을 모두 포괄.
  • 쓸 때 — 이름·메모·요청사항·사유 등 정형화되지 않은 입력.
  • 쓰지 말 것 — 고정 선택지(→ Select/Chips), 검색(→ Search), 숫자 증감(→ Stepper), 날짜(→ Date Picker).
  • 이름 — "텍스트 필드(Text Field)". iOS TextField/TextEditor·Android TextField 계열과 통일. "텍스트 박스/영역"은 웹 용어라 지양.

2. 해부 (Anatomy)

  • ① 라벨(옵션) — 필드 목적 명시, 상단
  • ② 컨테이너(well) — 편집 표면(회색 배경 · radius)
  • ③ 값 / 플레이스홀더
  • ④ 리딩 / 트레일링(옵션) — 아이콘·버튼(clear 등)
  • ⑤ 카운터(옵션) — 하단 우측
  • ⑥ 헬퍼 / 에러 문구(옵션) — 하단
  • ⑦ focus 보더 — 포커스 시 표시

6. 동작 (Behavior)

  • Auto-grow / 높이(멀티라인) — field.minHeight(52)에서 시작 → 내용 따라 확장 → field.maxHeight 도달 시 내부 스크롤(clip). maxHeight는 글자 한도가 다 들어갈 높이 이상이어야 함(한도 내 클립 금지 — 100자 안에선 절대 안 잘림). maxHeight 미지정이면 글자 한도가 자연 상한.
  • 카운터 배치 — well 안 하단 우측. 아래 A/B 중 택1(둘 다 허용):
    • A. 텍스트 아래 flow(권장·단순) — 카운터가 텍스트 바로 아래 별도 줄. 겹침 없음 → 하단 예약 패딩 불필요. 간격 margin-top 8~12. 본 프로토타입이 A 방식.
    • B. 코너 절대배치(Figma 구조 유지) — 우하단에 띄우고 텍스트가 밑으로 안 들어오게 하단 패딩으로 자리 확보. 단 하단 예약은 ~24 이하(현재 40은 과함 → 빈 블록처럼 보임).
  • 하드 리밋(옵션) — characterLimit 초과 입력 차단.
  • Focus — 보더 등장/제거, 배경색 유지.
  • 카운터 — 실시간, 현재값 Bold, 도달 시 브랜드블루. 가로 정렬은 필드 좌우 패딩(16)과 맞춤.
  • IME 조합입력 — 조합 중 글자수 카운트 주의(한글·일본어). 확정 기준으로 리밋 적용 권장.
  • 붙여넣기 — 한도 초과분 절단(전체 거부 X).
  • clear / submit — 트레일링 clear · 키보드 확정 콜백.

8. 접근성

  • 라벨 연결 — label을 accessibilityLabel/labelFor로 필드에 결합.

  • 탭 타깃 — 최소 44pt(iOS)/48dp(Android).

11. 구현 코드

iOS · SwiftUI
struct DSTextField: View {
    @Binding var text: String
    @FocusState private var focused: Bool
    var placeholder = "";  var label: String? = nil
    var characterLimit: Int? = nil
    var singleLine = false;  var isError = false
    var minHeight: CGFloat = 52;  var maxHeight: CGFloat? = nil   // maxHeight 초과 시 내부 스크롤

    var body: some View {
        VStack(alignment: .leading, spacing: 6) {
            if let label {                                    // 라벨(옵션)
                Text(label).spoqa(.medium, 13).foregroundColor(Color(hex: 0x5A6070))
            }
            VStack(alignment: .trailing, spacing: 8) {
                ZStack(alignment: .topLeading) {
                    if text.isEmpty {                         // 플레이스홀더
                        Text(placeholder).spoqa(.regular, 15)
                            .foregroundColor(Color(hex: focused ? 0x9DA0AE : 0x73788B))
                    }
                    field.spoqa(.regular, 15).foregroundColor(.black).focused($focused)
                        .onChange(of: text) { if let n = characterLimit { text = String($0.prefix(n)) } }
                }
                if let limit = characterLimit {               // 카운터(옵션)
                    HStack(spacing: 0) {
                        Text("\(text.count)").spoqa(.bold, 12)
                            .foregroundColor(Color(hex: text.count >= limit ? 0x32A2FA : 0x73788B))
                        Text("/\(limit)").spoqa(.regular, 12).foregroundColor(Color(hex: 0x73788B))
                    }
                }
            }
            .padding(16).background(Color(hex: 0xF5F6F7))
            .clipShape(RoundedRectangle(cornerRadius: 8))
            .overlay(RoundedRectangle(cornerRadius: 8)         // focus / error 보더
                .stroke(isError ? Color(hex: 0xFE4C00) : .black, lineWidth: (focused || isError) ? 1 : 0))
        }
    }
    @ViewBuilder private var field: some View {
        if singleLine { TextField("", text: $text) }
        else { TextEditor(text: $text).scrollContentBackground(.hidden)
                   .frame(minHeight: minHeight, maxHeight: maxHeight ?? .infinity) }  // 상한 도달 시 내부 스크롤
    }
}

// 사용 예시 — 요청사항(멀티라인 + 100자)
DSTextField(text: $note, placeholder: "예: 24인치 캐리어와 골프백이 2개 있어요", characterLimit: 100)
Android · Compose
@Composable
fun DSTextField(
    value: String,
    onValueChange: (String) -> Unit,
    modifier: Modifier = Modifier,
    placeholder: String = "",
    label: String? = null,
    characterLimit: Int? = null,
    singleLine: Boolean = false,
    isError: Boolean = false,
    minHeight: Dp = 52.dp,
    maxHeight: Dp? = null,                                // 상한 도달 시 내부 스크롤
) {
    var focused by remember { mutableStateOf(false) }
    val border = if (isError) Color(0xFFFE4C00) else Color.Black
    Column(modifier, verticalArrangement = Arrangement.spacedBy(6.dp)) {
        label?.let {                                          // 라벨(옵션)
            Text(it, fontFamily = Spoqa, fontWeight = FontWeight.Medium, fontSize = 13.sp, color = Color(0xFF5A6070))
        }
        Column(
            Modifier.fillMaxWidth().clip(RoundedCornerShape(8.dp))
                .background(Color(0xFFF5F6F7))
                .then(if (focused || isError) Modifier.border(1.dp, border, RoundedCornerShape(8.dp)) else Modifier)
                .padding(16.dp),
            horizontalAlignment = Alignment.End,
        ) {
            BasicTextField(
                value = value,
                onValueChange = { v -> onValueChange(characterLimit?.let { v.take(it) } ?: v) },  // 하드 리밋
                singleLine = singleLine,
                textStyle = TextStyle(fontFamily = Spoqa, fontSize = 15.sp, color = Color.Black),
                cursorBrush = SolidColor(Color.Black),
                modifier = Modifier.fillMaxWidth()
                    .heightIn(min = if (singleLine) 24.dp else minHeight, max = maxHeight ?: Dp.Unspecified)
                    .verticalScroll(rememberScrollState())   // maxHeight 초과분 내부 스크롤
                    .onFocusChanged { focused = it.isFocused },
                decorationBox = { inner ->
                    if (value.isEmpty()) Text(placeholder, fontFamily = Spoqa, fontSize = 15.sp,
                        color = Color(if (focused) 0xFF9DA0AE else 0xFF73788B))
                    inner()
                },
            )
            characterLimit?.let { limit ->                    // 카운터(옵션)
                Spacer(Modifier.height(8.dp))
                Row {
                    Text("${value.length}", fontWeight = FontWeight.Bold, fontSize = 12.sp,
                        color = if (value.length >= limit) Color(0xFF32A2FA) else Color(0xFF73788B))
                    Text("/$limit", fontSize = 12.sp, color = Color(0xFF73788B))
                }
            }
        }
    }
}

// 100자가 다 들어가는 높이 = 줄높이 × 최대줄수 + 상하 패딩
// 본문 15pt ≈ 22pt/줄, 좁은 폭(360)에서 100자 ≈ 6줄
private let contentMaxHeight: CGFloat = 22 * 6 + 16 * 2   // ≈ 164

TextEditor(text: $text)
    .frame(minHeight: 52, maxHeight: contentMaxHeight, alignment: .top)
    .fixedSize(horizontal: false, vertical: true)   // 내용 높이만큼 확장(auto-grow)
    .scrollDisabled(text.count < characterLimit)   // 한도 전엔 스크롤 없이 확장
// ⚠️ maxHeight를 이 값보다 작게 잡으면 100자 입력이 잘립니다.
//    Figma 컴포넌트 max(168 등)도 부족 → 상향 필요.
Android · Compose
// 100자 다 들어가는 max = 줄높이 × 최대줄수 + 상하 패딩
val maxH = with(LocalDensity.current) { 22.sp.toDp() } * 6 + 16.dp * 2   // ≈ 150+

BasicTextField(
    value = text,
    onValueChange = { if (it.length <= characterLimit) text = it },

)

카운터가 텍스트 바로 아래(8) 붙음 · 빈 여백 없음

수정 — 둘 중 택1(둘 다 허용):

  • A. 텍스트 아래 flow(권장·단순, 프로토타입 방식) — 카운터를 별도 줄에 두어 겹침 없음. 하단 예약 패딩 불필요.
  • B. 코너 절대배치 유지(Figma 구조) — 하단 예약 40 → ~24 이하로만 축소.
iOS · SwiftUI
// A. 카운터를 텍스트 아래 별도 줄에 flow — 하단 예약 불필요(권장)
VStack(alignment: .trailing, spacing: 8) {
    TextEditor(text: $text)
        .frame(minHeight: 52, maxHeight: contentMaxHeight)
    Text("\(text.count)/\(characterLimit)")
        .font(.system(size: 12, weight: .bold))
        .foregroundColor(text.count >= characterLimit ? .brandBlue : .counterGray)
}
.padding(16)   // 상하좌우 균일 — 하단만 큰 예약 없음

// B. 코너 유지 시엔 예약만 축소(40 → 24)
ZStack(alignment: .bottomTrailing) {
    TextEditor(text: $text)
        .padding(EdgeInsets(top: 16, leading: 16, bottom: 24, trailing: 16)) // 40→24
    Text("\(text.count)/\(characterLimit)")
        .font(.system(size: 12, weight: .bold))
        .padding([.trailing, .bottom], 16)
}
Android · Compose
// A. 카운터를 텍스트 아래 별도 줄에 flow — 하단 예약 불필요(권장)
Column(Modifier.padding(16.dp), horizontalAlignment = Alignment.End) {
    BasicTextField(value = text, onValueChange = { /* … */ },
        modifier = Modifier.fillMaxWidth().heightIn(min = 52.dp, max = maxH))
    Spacer(Modifier.height(8.dp))
    Text("${text.length}/$characterLimit", fontWeight = FontWeight.Bold,
        color = if (text.length >= characterLimit) BrandBlue else CounterGray)
}

// B. 코너 유지 시엔 예약만 축소(40 → 24)
Box(Modifier.fillMaxWidth()) {
    BasicTextField(value = text, onValueChange = { /* … */ },
        modifier = Modifier.padding(start = 16.dp, top = 16.dp, end = 16.dp, bottom = 24.dp)) // 40→24
    Text("${text.length}/$characterLimit", fontWeight = FontWeight.Bold,
        modifier = Modifier.align(Alignment.BottomEnd).padding(16.dp))
}

수용기준 — 마지막 텍스트 줄과 카운터 간격이 과하게 벌어지지 않음. 텍스트와 카운터가 겹치지 않음. 가로 정렬은 필드 좌우 패딩(16)과 일치.

두 이슈는 사실 한 뿌리 — 입력창이 auto-grow 대신 작은 고정/클립 박스로 구현돼 (1) 텍스트가 잘리고 (2) 하단 여백이 블록처럼 보입니다. auto-grow + 한도 다 담는 max + 카운터 배치 A면 둘 다 해결됩니다.

7카피 & i18n

키문안
헤더요청 내용에서 참고할 점 {N}개를 찾았어요
분석 중요청 내용 분석 중
empty / noResult요청 내용을 분석해 참고할 만한 정보를 안내해 드려요. (✦ 회색 별)

요청사항·탑승사유가 같은 컴포넌트를 공유하므로 어시스트 카피는 기능 중립어 "요청 내용"으로 통일(앱바 타이틀만 화면별로 다름). {N}은 카드 개수, 1개도 "1개"로 표기(복수 규칙 단순화).

8접근성

  • 대비(흰 배경): 입력 #000 ≈21:1 · 제목 #262A38 ≈14:1 · 본문 #383D4F ≈10:1 — 모두 AA 통과. 키워드/카운터 #73788B ≈4.6:1(AA 경계). 어시스트 헤더 #868B9C ≈3.4:1은 보조 라벨로만(핵심 정보 아님).
  • 탭 타깃: 액션칩·유도칩·CTA 최소 44×44pt(iOS)/48dp(Android).
  • 스크린리더: 카드는 "키워드, 제목, 본문" 순서로 묶어 읽기(그룹). 카운터는 "N/100자 입력됨". 어시스트 ✦는 accessibilityHidden.
  • 모션: 스켈레톤 shimmer·페이드는 prefers-reduced-motion/Reduce Motion에서 생략.

9엣지 케이스 & 세션

  • 최대 글자: 요청사항 100 / 탑승사유 150. 한도 도달 시 카운터 #32A2FA(입력은 계속 막힘, 에러 톤 아님).
  • 오버플로우: 카드가 많아 키보드 뒤로 가려지면 "N개 안내 더 있어요 ↓" 유도칩nice-to-have.
  • 세션 저장 규칙(플로우 정의): 저장된 요청사항은 세션 내 유지 · 작성완료=저장, 상단 뒤로가기=미저장 · 빈 곳 클릭=필드 디폴트+키보드 내림. 세션 이탈 = 예약 성공 / 예약 홈 복귀 / 앱 종료. 작성 중·기존 예약 불러오기에서는 값 미저장.
